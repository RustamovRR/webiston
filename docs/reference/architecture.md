# Webiston — Architecture

> Structure, boundaries, and the module contract. Read before any structural
> change. Rules that a gate enforces live in `code-rules.md`; this doc explains
> the shape and the *why*.

---

## 1. Layout

A **hybrid monorepo**: one deployable Next.js app at the root, shared packages
beside it, and a browser extension under `apps/`.

```
webiston/
├── src/                          # THE Next.js app (not apps/web — see adr/0001)
│   ├── app/
│   │   ├── (app)/[locale]/       # i18n routes (uz default, en prefixed)
│   │   │   └── tools/<slug>/     # one route folder per tool
│   │   ├── books/[...slug]/      # book reader (outside [locale])
│   │   ├── api/search/           # search endpoint
│   │   ├── layout.tsx            # root layout: metadata, JSON-LD, fonts
│   │   ├── manifest.ts           # PWA manifest
│   │   └── globals.css           # ⚠️ the ONLY stylesheet + the token block
│   ├── components/
│   │   ├── shared/               # app-specific composites (Header, Search, …)
│   │   ├── ui/                   # thin re-export shims → @webiston/ui (legacy)
│   │   └── mdx/                  # MDX renderers (CodeBlock, Callout, TOC, …)
│   ├── modules/tools/{ToolName}/ # feature modules — one folder per tool
│   ├── lib/                      # content processing, search, utils
│   ├── hooks/  stores/  types/  constants/  i18n/
│   └── middleware.ts             # next-intl locale routing
├── content/                      # 226 MDX chapters, 3 books, + _meta.json each
├── messages/                     # uz/en translation JSON + index.js merger
├── packages/
│   ├── ui/                       # @webiston/ui — primitives/ + composites/ + utils/
│   └── transliteration/          # @webiston/transliteration — pure TS, zero deps
├── apps/extensions/latin-cyrillic/  # Chrome extension (WXT)
├── public/  scripts/
└── (config: next.config.ts, tsconfig.json, biome.json, oxlint.json,
    vitest.config.ts, lefthook.yml, commitlint.config.mjs, next-sitemap.config.js)
```

## 2. Dependency direction

```
   ┌──────────────────────┐   ┌──────────────────────┐
   │  apps/extensions/*   │   │   src/ (Next.js)     │
   └──────────┬───────────┘   └──────────┬───────────┘
              └──────────┬───────────────┘
                         ▼
              ┌──────────────────────┐
              │      packages/       │
              │  ui · transliteration│
              └──────────────────────┘
```

| Rule | |
| --- | --- |
| ✅ | `src/` and `apps/*` may import `packages/*` |
| ❌ | `packages/*` may **never** import `src/` or `apps/*` |
| ❌ | `apps/*` may not import each other |
| ❌ | the `@/` alias does not exist inside `packages/` — do not use it there |

Nothing enforces this automatically today. It is a review rule; a
dependency-cruiser style gate is in the backlog.

## 3. The two packages

### `@webiston/transliteration`
Pure TypeScript Latin↔Cyrillic engine. **Zero runtime dependencies — keep it
that way.** Built with `tsup` to CJS + ESM + DTS. Consumed by both the web app
and the Chrome extension, so anything added here ships to extension users: no
DOM assumptions, no framework imports. It holds the repo's only test suite
(6 files in `__tests__/`).

### `@webiston/ui`
Shared UI: `primitives/` (Shadcn/Radix wrappers — button, dialog, select, …),
`composites/` (BaseModal, CopyButton, InfoCard, StatsDisplay), `utils/` (`cn`).
Consumed **source-level** — no build step; Next compiles it directly. It owns
the Radix, CVA, and framer-motion dependencies.

**Two import paths exist for the same components.** `@webiston/ui` is canonical;
`src/components/ui/*` is a set of 1–17 line re-export shims kept for backward
compatibility with older imports. New code uses `@webiston/ui`. Collapsing the
shim layer is a backlog item — it is a real cleanup, but it touches many files,
so it is not a drive-by.

## 4. The tool module contract

Every tool is self-contained under `src/modules/tools/{ToolName}/`:

```
{ToolName}/
├── components/        # dumb UI
├── hooks/             # use{ToolName}.ts — all the logic
├── stores/            # Zustand, only when state outlives the tree
├── types/  constants/  utils/
├── {ToolName}.tsx     # composition root
└── index.ts           # named exports only
```

A tool becomes reachable only when it has a route at
`src/app/(app)/[locale]/tools/<slug>/page.tsx`, is present in `tools-list.json`
(regenerated by `scripts/update-tools-list.js` during `postbuild`, which feeds
the sitemap), and has `messages/tools/<slug>/{uz,en}.json` wired into
`messages/index.js`.

**Four tool routes are currently parked** behind a `_`-prefixed folder name
(`__http-status`, `__keycode-info`, `__user-agent-analyzer`, `__website-status`).
A leading underscore makes a folder *private* in the Next.js App Router, so those
pages are not routed. Their modules (3,846 LOC) still build and still count
against the codebase. Whether they get finished or removed is an open decision —
see `docs/roadmap/backlog.md`. **Do not rename or delete them without asking.**

## 5. Rendering model

Next.js App Router with the **React Compiler on** (`next.config.ts`
`reactCompiler: true`) — so no manual `useMemo`/`useCallback` for stability.

Server Components are the default and the point: this site's value is
server-rendered prose. **101 of 208 `.tsx` files in `src/` currently carry
`'use client'` (49%)**, which is the main structural debt. The rule and the
reasoning are in `code-rules.md § 4` and `seo-performance.md § 2`.

Other framework facts worth knowing before you change config:

- `output: "standalone"` — the deploy artifact is self-contained.
- `images.unoptimized: true` — Next's image optimizer is **off**; sizing and
  compression are your responsibility (`seo-performance.md § 4`).
- `pageExtensions` includes `md`/`mdx`.
- `/docs/:path*` permanently redirects to `/books/:path*`.

## 6. Build & tooling pipeline

```bash
pnpm dev          # next dev --turbopack --port 9999
pnpm build        # next build
#   └ postbuild:  update-tools-list.js → next-sitemap → build-search-index.js
pnpm check        # biome check .        (read-only)
pnpm format       # biome format --write .
pnpm lint         # oxlint src/ packages/ apps/
pnpm typecheck    # tsc --noEmit         (excludes apps/extensions — tsconfig:23)
pnpm test         # vitest run
pnpm ext:dev|build|zip   # WXT extension
```

Biome formats; oxlint lints. Biome's `files.includes` **excludes** `*.css`,
`*.md`, `*.mdx`, and `content/`.

Git hooks (`lefthook.yml`): pre-commit → oxlint + biome format on staged files;
commit-msg → commitlint; pre-push → typecheck + test, in parallel.

**There is no CI.** No `.github/workflows`, no `vercel.json` in the repo. The
pre-push hook is the only automated gate, and `--no-verify` bypasses it.

## 7. Branch reality (read this before trusting any doc)

At the time of writing, branches disagree about the build system:

| Branch              | Build system                     | Steering docs                          |
| ------------------- | -------------------------------- | -------------------------------------- |
| `dev` (current)     | direct scripts, **no `turbo.json`** | `.kiro/steering/{product,tech,structure}.md` |
| `origin/fix/issues` | **Turborepo** (`turbo.json`, `packages/ui/turbo.json`), newer deps | `.kiro/steering/{ai-instructions,code-rules,structure}.md` |

`dev` is also 3 commits ahead of and 3 behind `origin/main`.

Always run `git rev-parse --abbrev-ref HEAD` and check whether `turbo.json`
exists before assuming which commands work. Reconciling this is the **first**
item in `docs/roadmap/active.md` — refactoring on a branch that is about to be
rebased wastes the work.

Kept for the Kiro IDE, but verified stale on `dev` (2026-07-29):

- `tech.md` claims Next 15.3.3 / React 19.1.0 / TS 5.8.3 / Tailwind 4.1.8 —
  actual: **16.1.6 / 19.2.4 / 5.9.3 / 4.2.1**.
- `tech.md` and `product.md` claim **Russian (`ru`)** support — it does not exist.
- `tech.md` says pre-push is "typecheck + full lint" — it is **typecheck + test**.
- `structure.md` lists 2 books — there are **3** — and a `src/lib/config/`
  directory that does not exist.
- Neither mentions `packages/` or `apps/extensions/`, which do exist on `dev`.

**`CLAUDE.md` + `docs/` are the source of truth.** If a steering file disagrees,
the steering file is wrong. Deciding whether to update or retire `.kiro/` is an
open item in the backlog — it needs the owner's call, since it depends on
whether Kiro is still in use.
