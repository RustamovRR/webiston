## Needs a decision from the owner (blocking — do not guess)

- [!] **The brand colour.** `--primary` is stock Shadcn grey
      (`globals.css:376`, `oklch(0.205 0 0)` — zero chroma), so every primary
      button on the site is black-or-white. Picking the hue unblocks design
      Phase A. Must pass WCAG AA on both backgrounds.
- [!] **The four parked tools.** `__http-status`, `__keycode-info`,
      `__user-agent-analyzer`, `__website-status` sit behind `_`-prefixed
      (private) route folders, so they are unreachable in production — ~3,800 LOC
      that still builds and still gets linted. Finish them, or remove them
      (removal needs explicit approval). They are also among the worst files for
      hardcoded colour, so the answer decides whether that cleanup is worth doing.
- [!] **The `/books` i18n story.** All 226 chapters live at `src/app/books/`,
      a *sibling* of `(app)/[locale]/` — so they are outside the locale segment
      entirely and the middleware matcher does not cover them. Are the books
      Uzbek-only forever, or does `/en/books` need to exist? The answer changes
      the canonical/hreflang work in `active.md` P0.
- [!] **Image optimization.** `next.config.ts:25` sets `images.unoptimized: true`.
      Turning it on is a real win for a content site but interacts with
      `output: "standalone"` and the deploy target. ADR-sized.
- [!] **`.kiro/steering/*` — update or retire?** Verified stale: wrong versions
      for Next/React/TS/Tailwind, claims Russian support that does not exist,
      2 books instead of 3. Depends on whether Kiro is still in use.
- [!] **Generated artifacts in git.** `public/sitemap.xml`, `public/search-index.json`
      and `tools-list.json` are regenerated by `postbuild` on every build but are
      committed, so every build dirties the tree. Commit them (deploy needs them
      without a build step) or ignore them (clean diffs) — pick one.

## Blocked on upstream

- [>] **Drop `experimental.useTypeScriptCli`.** `next.config.ts:18` carries it
      because Next 16.2.12 cannot use the TypeScript 7 compiler API. Remove the
      flag once Next supports TS 7 natively. Risk while it stands: an
      `experimental` flag can be renamed in any Next minor, and there is no CI to
      catch it — the build would fail at deploy time.
- [>] **Restore `tsup --dts`.** `packages/transliteration` now emits declarations
      with `tsc --emitDeclarationOnly` because tsup's bundled
      `rollup-plugin-dts@6.1.1` targets typescript 5.7 and crashes on TS 7.
      Revert to the one-step build when tsup ships a TS 7-compatible dts plugin.
