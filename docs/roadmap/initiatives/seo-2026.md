## Phase 1 — `[~]` Mechanical defects (shipped 2026-08-07 except where noted)

The two things structurally blocking traffic were the SERP title on 79% of the
site, and the locale correctness of everything under `/ru`.

- `[x]` **Book chapter titles: median 104 → 77 chars.**
  `src/app/books/[...slug]/page.tsx:160` built ``​`${title} | ${tutorialInfo.title}`​``
  and the root template appended `| Webiston` on top. New
  `getTutorialShortTitle()` in `src/lib/mdx.ts` supplies the bare book name
  (`Fluent React` instead of `Fluent React: Zamonaviy React Dasturlash`), and
  **OpenGraph keeps the full title** — a share card is read, not truncated, so
  the two surfaces get two different strings.

  | | before | after |
  | --- | ---: | ---: |
  | median `<title>` | 104 | **77** |
  | max | 148 | **110** |
  | over 60 chars | 226 / 228 | **180 / 228** |

  **Do not read that last row as "46 chapters fixed" — the honest decomposition
  is different and it matters for what to do next.** Truncation cuts from the
  end and the chapter title comes first, so a suffix can never rescue a chapter
  whose own title is already too long:
  - **53 chapters have titles over 60 characters on their own.** That is an MDX
    frontmatter content problem across `content/**` and no metadata change can
    touch it. It needs an editorial pass — the worst is 84 characters.
  - **127 chapters were pushed over by the suffix.** For those the win is that
    the book name now renders *completely* instead of being cut mid-word 40
    characters into a subtitle, and the brand is much closer to fitting.

  So: the suffix stopped being garbage, which was the fixable half. The
  remaining half is writing.
- `[x]` **Breadcrumbs on `/ru` pointed at Uzbek URLs — 14 tool modules.**
  Every `generateBreadcrumbSchema` branched `locale === "en" ? "/en" : ""`, a
  binary with no answer for a third locale. Google discards a `BreadcrumbList`
  whose terminal URL is not the page it is served on, so the rich result was
  lost across the whole Russian tree — silently, because the markup is *valid*.
  Replaced by `toolBreadcrumbSchema(locale, slug, name)` in `src/lib/seo.ts`,
  which derives every URL from `localeUrl` — **the same function the canonical
  comes from**, so the trail cannot disagree with it. Russian crumb labels come
  from each tool's existing `COPY.ru.title`, shortened to a label.
  Verified by executing all 14 modules across all 3 locales: **42/42**.
- `[x]` **`inLanguage: ["uz","en"]`** — stale through the entire Russian launch.
  Fixed in the 14 tool schemas and `src/app/layout.tsx`. (`/books` uses the
  scalar `inLanguage: "uz"`, which is **correct** — it is Uzbek-only by design.)
- `[x]` **hreflang test derived from `LOCALES`.** `src/lib/seo.test.ts` looped a
  literal `["uz","en"]`, so it kept passing after `ru` shipped while saying
  nothing about it. Now asserts reciprocity across every served locale plus a
  byte-identical language set on every variant — the failure mode that actually
  costs traffic.
- `[x]` **`next-sitemap.config.js` locale list** — added `ru`. Note this is
  intent, **not repair**: `/ru/*` is prerendered and next-sitemap
  auto-discovers it, so the sitemap already carried 18 `/ru` URLs. The list is
  load-bearing only for the unprefixed `uz` URLs, which are not prerendered.
- `[x]` **The four inline-metadata routes** — `/tools`, `qr-generator`,
  `json-formatter`, `password-generator` served **one hardcoded Uzbek title to
  all three locales**, including the tools hub and the #2 tool. Ported to
  `seo/` segments with real `{uz,en,ru}` copy, following the 14 existing
  modules. They also carried the last 4 of the 18 breadcrumbs.
  Verified in the built HTML: 12/12 pages have three distinct titles *and*
  three distinct descriptions in the right language, one self-referencing
  canonical each, a byte-identical 4-value hreflang set per route, and **60/60
  JSON-LD blocks parse**.
  Three defects of the same class turned up during the port and were fixed:
  `getFaqItems` had `uz`/`en` only on three of the four, so `/ru` *rendered and
  published* Uzbek Q&A; `<LocaleMessages>` was not receiving `locale`, so those
  routes shipped the Uzbek message bundle to `/en` and `/ru` clients; and the
  pages imported from the `@/modules/tools` barrel, which pulls all 21
  `'use client'` modules.
- `[x]` **`/ru` breadcrumbs, measured end-to-end.** All **17** `/ru` tool pages
  now have a breadcrumb whose terminal URL equals the page's own canonical —
  it was **0 of 17**. `og:locale` is `ru_RU` on all 17.
- `[>]` **`<html lang>` follows the locale.** Deferred *again*, now with a
  better reason than last time: Google states it "uses the visible content of
  your page to determine its language. We don't use any code-level language
  information such as `lang` attributes, or the URL." **This is an accessibility
  fix, not an SEO one**, and the price is unchanged — `/books` sits outside
  `[locale]`, so it needs multiple root layouts and a hard navigation between
  the two trees. Do not let an SEO argument buy that.

## Phase 2 — `[x]` Brand assets (shipped 2026-08-07)

The 2026 Terminal mark existed only as markup in `Logo.tsx`; every icon in
`public/` was the July-2025 logo.

- `[x]` **`src/app/icon.svg`**, hand-authored. Not a scaled copy of the header
  lockup — the header badge is `--card` with a 1px border that is 0.44 device px
  at 16×16, i.e. invisible, leaving a near-white badge on a white tab strip. The
  icon badge is solid `--primary` and holds its contrast internally. The `w` is
  a stroked path, not `<text>`: Inter is not a system font and an SVG used as an
  image resolves fonts against whatever is installed locally.
  Proportions chosen by **rendering six variants at 16px and looking at them**.
- `[x]` **`metadata.icons` removed from `src/app/layout.tsx`** — the one
  non-obvious step. Next resolves file-convention icons behind
  `if (!resolvedMetadata.icons)` (`resolve-metadata.js:812`), so *any* layout
  setting that key silently discards every convention icon in the tree. With it
  in place, `icon.svg` would have emitted nothing at all.
- `[x]` **`scripts/generate-icons.mjs`** — run by hand, outputs committed.
  Emits `favicon.ico` (**single-frame 32×32**: Next reads the first directory
  entry for `sizes=`, and the old 3-frame 16/32/48 file would have advertised
  `sizes="16x16"` and lost the Chrome tie-break against the SVG),
  `apple-icon.png` (180, opaque, full-bleed), `icon-192/512`, `icon-mask`
  (content inside the central 80% for Android's circular crop), and
  `public/logo.png` **regenerated in place at 512×512 on a white plate**, which
  fixes all ~20 JSON-LD references without touching a line of code. 209 KB → 10 KB.
  It reads the geometry out of `icon.svg` rather than restating it, so the
  favicon and the PNGs cannot drift into two different logos.
  `sharp` is resolved from the pnpm store by glob — it must not become a dependency.
- `[x]` **One theme colour instead of three.** There were `#3b82f6` (Tailwind
  `blue-500`, not a brand hue) in the manifest, `#ffffff` in
  `public/site.webmanifest`, and `#000000` smuggled through `metadata.other`,
  which bypasses Next's "move it to viewport" warning by being an untyped
  `Object.assign`. Now one `export const viewport` with a light/dark pair
  tracking `--background`.
- `[x]` **Manifest corrected.** It listed `/icons/qr-generator.png` and
  `/icons/password-generator.png` — **neither file has ever existed** — and put
  `purpose: "maskable"` on an unpadded icon, so Android was cropping the mark.

## Phase 2b — `[x]` Mobile (found while auditing before a production push)

- `[x]` **The hamburger opened an empty screen on every page except a book
  chapter.** `MobileMenu` gated its entire body on `tutorialId`, which is
  `params.slug[0]` and so exists only under `/books/[...slug]`. Measured in the
  browser at 375px: the panel opened, `body` scroll locked, and the panel
  contained **0 links and 0 characters** — an opaque full-screen nothing whose
  only exit was finding the 36px button again.
- `[x]` **Below 768px there was no language switcher, no search and no theme
  toggle — at all.** They live in a `hidden md:flex` row, and the menu that was
  meant to carry them was the empty one above. Measured, not inferred. On a
  locale we shipped a week earlier, on the device most of the audience uses,
  **there was no way to reach `/ru`.** The menu now always carries Search, the
  book list, Tools, the language switcher and the theme toggle, with the
  chapter tree added on top when a book is open.
- `[x]` **Three smaller defects in the same component**: `mt-14` (56px) against
  a 64px `--header-height`, so the panel sat 8px under the bar; `100vh` rather
  than `100dvh`, so the bottom row hid behind mobile browser chrome; and a
  hardcoded Uzbek fallback string served to `/en` and `/ru`.
- `[x]` **Accessibility**: the button had no accessible name and no
  `aria-expanded` — a screen reader announced "button" and nothing else. Now
  labelled per state, with `aria-controls`, `role="dialog"`, `aria-modal`,
  Escape-to-close, `inert` while closed (so its links are not tabbable on every
  page), and a close on browser back/forward that no click handler can see.
  Tap targets in the menu are 44px; the shared controls are scoped up to 44
  inside the panel only, leaving the desktop header alone.

**Verified at 375×812 in the browser**, not assumed: homepage, `/tools`,
`/tools/latin-cyrillic` and the heaviest book chapter all have
`documentElement.scrollWidth === 375` — no page-level horizontal scroll. The
217 over-wide elements on that chapter are all inside `pre.shiki`, which
scrolls in its own box.

## Phase 2c — `[x]` Every internal link dropped `/ru` and `/en` visitors into Uzbek

Found while testing the mobile menu, and **bigger than the menu**: from
`/ru/tools/qr-generator`, clicking the header's *Полезные инструменты* landed on
`/tools` — Uzbek title, Uzbek body, `NEXT_LOCALE=ru` cookie present and useless
(`localeDetection: false`). The header, the footer and the logo all used
`next/link` with bare `/tools` and `/`, so **the first link a visitor clicked
threw them out of their own language**, on every page.

- `[x]` `Header`, `Footer` and `Logo` now use `Link` from `@/i18n/navigation`.
  `/books/**` deliberately keeps `next/link` — it is Uzbek-only and lives
  outside `[locale]`, so prefixing it would 404.
- `[x]` **The locale has to be passed explicitly**, and this is the same root
  cause that already made `Header` take a `locale` prop instead of calling
  `useTranslations`: the chrome renders from `[locale]/layout.tsx`, whose
  `setRequestLocale` does not reach it, so next-intl's ambient locale there is
  the *default*. `Link` reads that ambient value, so it produced `/tools` on
  `/ru` for exactly the reason the header once rendered Uzbek on `/en`.
- `[x]` **…but passing it forces the prefix**, and `localePrefix` is
  `"as-needed"`. The first attempt emitted `/uz/tools` and `/uz` — URLs whose
  only purpose is to 307 back, which `next-sitemap.config.js` already excludes
  for that reason. Caught in the built HTML before it shipped. The rule now
  lives once, in `chromeLinkLocale()` in `src/i18n/navigation.ts`: pass it for
  prefixed locales, omit it for the default.

Measured in the built HTML, per locale: `uz` 3×`/tools` + 2×`/` and **zero**
`/uz/` URLs; `en` 3×`/en/tools` + 2×`/en`; `ru` 3×`/ru/tools` + 2×`/ru`;
`/books/**` unprefixed everywhere.

## Phase 2d — `[x]` Image zoom: `medium-zoom` → `react-medium-image-zoom`

Reported: a figure opened on mobile could not be closed and covered the page.

The old library was last published **2023-11-16** and is driven imperatively —
`mediumZoom(el)` on mount, `zoom.detach()` on unmount. `detach()` does **not**
close an open zoom, so unmounting while zoomed (a client navigation, an HMR
update) orphaned a full-screen `z-index: 9999` overlay with nothing left to
dismiss it.

The replacement is a React component, so there is no attach/detach pair to get
wrong. It renders into a native `<dialog>` — Escape, focus trap, top layer and
inertness for free, plus swipe-to-dismiss on touch. Maintained (2026-06), **zero
runtime dependencies**, React 19 in peers.

Rejected, with reasons: `framer-motion`'s `layoutId` needs no new dependency but
framer-motion is **not in the book route's bundle**, so 226 chapters would start
paying ~40 KB for 94 figures. The View Transitions API is Baseline (2025-10-14,
Firefox 144) and the repo already uses it in `ThemeToggle`, but it animates
between two states — the dialog semantics would still be hand-written.

Verified against a **production build**, open → close, desktop and mobile:
native `<dialog>` with `:modal` true, overlay resolving to `--background`,
buttons to `--card`/`--border-strong`, and after close **0 orphaned overlays**,
body scroll restored, page interactive again.

⚠️ **Two of my own readings during this were artifacts, not findings.** The
Browser pane repeatedly collapsed to a 0×0 viewport, which (a) made every
element measure 0 and (b) meant lazy images never loaded — and the zoom library
marks content `not-found` until the image *has* loaded
(`hasImage()` requires `state.loadedImgEl !== undefined`). Check
`window.innerWidth` before trusting any measurement taken through that pane.

## Phase 3 — `[ ]` Structure (the biggest remaining lever)

- `[ ]` **Internal linking.** Measured in the built HTML: `/tools/latin-cyrillic`
  has **1** inbound internal link site-wide; 10 of 17 tools have exactly one;
  `grep -rn "/tools/" content/` → **0**. 226 chapters of authoritative content
  pass no equity to the 17 pages we want ranking. Two changes: a 4-item
  `RelatedTools` strip per tool page (**not** all 17 — that is a doorway
  pattern), and contextual links from the chapters that genuinely relate
  (JSON chapters → `json-formatter`, encoding → `base64-converter`).
- `[ ]` **Book chapters have zero page-level structured data.** 228 pages emit
  4 inherited `ld+json` blocks and nothing of their own. Add `BreadcrumbList`
  (a live rich result) and `TechArticle` with a **named translator**,
  `datePublished`, `isPartOf`. The 17 tool URLs have 6 schemas each; the
  226-page library has none.
- `[ ]` **`/about` + `/contact` with a named human.** The largest E-E-A-T gap:
  who translated three programming books into Uzbek, and why. Scope
  `Organization` JSON-LD to `/` and `/about` rather than every page.
- `[ ]` **Yandex + Bing Webmaster + IndexNow.** The reason is **Uzbekistan's own
  22% Yandex share**, not Russia. Site region = **No region** (we cannot
  honestly claim one). IndexNow is ~30 lines in `postbuild`; Google does not
  participate, but Bing's index feeds Copilot, ChatGPT Search and Perplexity.
